言泉输入法 Linux 版是一个面向 Linux 桌面的实验性中文拼音输入法。原生的 IBus 与 Fcitx 5 适配器共用一个以 Free Pascal 编写的引擎服务，引擎移植自[言泉输入法 Windows 版](https://github.com/shenmin/cassotis-ime)，词库由 [Cassotis Lexicon](https://github.com/shenmin/cassotis-lexicon) 生成。候选排序全部在本机 CPU 上完成，核心是一个由本项目训练的字符级语言模型。

当前开发版本 2.1.0 对齐言泉输入法与 Cassotis Lexicon v2.3.0，改进逐键输入的词语选择、减少不合理的短语候选，并在保留繁体输出的同时统一语言模型的评分文字。仍使用原有的一个语言模型和七组紧凑排序参数。已发布的安装包见 [Releases](https://github.com/shenmin/cassotis-ime-linux/releases)。

项目当前重点：
- 跟进 Windows 版的每次发布，并用同一套基准测试核对两边是否一致；
- 与 GNOME、KDE 等桌面上的 IBus 和 Fcitx 5 原生集成；
- 提供 amd64 与 arm64 安装包，不联网、不需要 GPU 即可使用。

## 名称来源
英文名 **Cassotis** 源自 Delphi 神庙内的一眼圣泉。传说女祭司皮媞亚（Pythia）在发布神谕前会饮用此泉水，以进入通灵状态。这眼泉水被视为预言与灵感的真正源头，也是神谕诞生之地，呼应了从 Delphi 到人类语言的路径。

中文名 **言泉** 既契合 Cassotis 作为预言之泉的意象，也取“言如泉涌”的寓意，寄托了对流畅、智能输入体验的期许。

## 主要特性
- **IBus 与 Fcitx 5**：两个适配器连接同一个引擎服务，共用设置、词库和学习数据。桌面会话中只需启用其中一个框架。
- **候选面板**：候选由 IBus 或 Fcitx 5 绘制，随桌面主题显示；每页 3 至 9 个候选（默认 9 个），可用 `-/+`、`[/]`、`,/.` 或 `Shift+Tab/Tab` 翻页。
- **英文识别**：中文全拼、半角输入时，英文单词和名称（如 `pro`、`markdown`、`Effie`）、带大写字母的输入以及曾按字母上屏的输入，会作为不带编号的候选显示在编号候选之前。输入没有整词中文读法时默认选中，空格原样上屏；有中文读法时（如 `bug`、`mac`），由语言模型结合上文在字母与中文之间权衡。中文候选的数字编号不变，原样上屏的字母不会被记为中文用户词。默认开启，可在设置中关闭；双拼仍按中文处理。
- **一键补全**：在候选之外只显示一个可信的续写方案，按设置的 `Tab` 或反引号键接受。词库补全和强转移补全立即显示；语言模型随后在后台重新排序或延长，把握不足时不提示。
- **诗词补全**：输入已收录诗句的开头可以补全整句；完整输入一句后，可以提示带标点的下一句诗，而不是泛化生成的后缀。
- **长句**：受词库约束的路径搜索给出完整候选（例如 `womenjintian` → `我们今天`），同时保留前缀词和单字供分段上屏。语言模型在完整候选中选择，再对照输入的拼音和输入位置之前的文字，修正少量同音错字。
- **短词**：多个精确候选竞争时由语言模型判断，光标前有已上屏的文字时一并参考。
- **繁体输入**：候选和上屏文字使用台湾繁体字形。语言模型以对应的简体文字读取候选及上文，后台补全也采用同样处理，避免仅因繁体字形而影响评分。
- **短语**：三到五个音节、词库里没有的输入（例如 `jiuguize` → `旧规则`），由词库中的词拼出若干整句方案，语言模型结合光标前的文字选出一个，再对照输入的拼音修正同音字；选过的非首选短语会被记住。
- **拼音方案**：全拼、首字母简拼（例如 `jt` → `今天`）及六种双拼方案（微软、小鹤、自然码、搜狗、紫光和拼音加加）共用候选排序与学习数据；11 组模糊音可分别开启。`lue`/`nue` 可代替 `lve`/`nve`，`jv`/`qv`/`xv` 可代替 `ju`/`qu`/`xu`；分隔符 `'` 始终保留音节边界。
- **词库与学习**：简体、繁体基础词库与用户词库相互分离。学习到的词通过 OpenCC 随所选简繁模式显示；选中已学习的候选后按 `Ctrl+Delete` 可将其删除。
- **文档内适应**：框架提供的光标前后文字，会让当前文档中反复出现的词语和续写更容易打出。这些信息只留在内存中，按输入上下文隔离，从不写入磁盘。
- **快捷输入**：`ufh` 符号、`uxh` 序号、`usx` 数学符号、`ujt` 箭头、`udw` 单位、`ubd` 中文标点，`urq`/`usj`/`uxq` 输入当前日期、时间和星期；`i123.45` 或 `v123.45` 转换中文数字及金额大写。双拼用 `Shift+U/I/V` 进入。详见[快捷输入说明](CONFIGURATION.CN.md#快捷输入)。
- **中文标点**：中文标点、半角输入时，连续输入数字后的句号自动变为小数点；保持半角的符号可在设置中修改，默认的 Markdown 预设为 ``-#*+_=`~[]<>|@``，逗号、句号、圆括号和引号仍按中文习惯输入。
- **设置**：GTK 3 设置程序提供 Linux 上支持的各项选项；每个功能快捷键都可单独关闭，并保留原有按键设置。
- **自定义短语**：用字母快捷码输入固定短语、地址或多行文本。精确匹配后显示在补全行，按设定的 `Tab` 或反引号键原样上屏，不改变编号候选，也不自动学习为用户词。设置页支持排序编辑、JSON 导入导出；诊断选项集中在“高级”页。详见[自定义短语](CONFIGURATION.CN.md#自定义短语)。
- **完全本地**：不联网，不需要 GPU。从第一个按键起就有词库候选；语言模型尚未加载或不可用时，候选照常给出，只是不经过语言模型排序。

## 下载与安装

在 [GitHub Releases](https://github.com/shenmin/cassotis-ime-linux/releases) 下载安装包及其校验值。每个安装包都同时包含 IBus 与 Fcitx 5 适配器、词库和语言模型。先按系统环境选择安装方式：

| 系统环境 | 下载格式 | 安装方式 |
| --- | --- | --- |
| 依赖兼容的 Debian、Ubuntu 及衍生系统 | `.deb` | [APT 安装](#debian-installation) |
| SteamOS 桌面模式等系统目录只读的环境 | `.tar.gz` | [用户目录安装，无需 sudo](#user-installation) |
| 其他具有兼容运行库、系统目录可写的发行版 | `.tar.gz` | [便携包的系统安装](#system-installation) |

便携包中的二进制与同架构的 `.deb` 相同，均为动态链接，需要兼容的运行库，并非适用于所有发行版的通用包。请先运行便携安装器的依赖预检；若所附二进制不兼容，请从源码构建。各种升级和卸载方式都会保留用户词库和设置。

<a id="debian-installation"></a>

### Debian / Ubuntu：APT 安装

下载与系统架构相符的 `.deb`，将本地计算的 SHA-256 与 Release 资产信息中显示的摘要核对一致后，再用 APT 安装：

```bash
arch="$(dpkg --print-architecture)"  # 输出 amd64 或 arm64
package="cassotis-ime_2.0.0_${arch}.deb"
sha256sum "${package}"
sudo apt install "./${package}"
```

安装器会刷新当前活动的 IBus 和 Fcitx 5 桌面会话。在使用 IBus 的 GNOME 桌面中，Cassotis 会直接加入输入源列表，无需重启系统或重新登录，也不会切换当前输入源。如果安装时没有活动的图形会话，则会在下次登录时自动发现 Cassotis。按 `Super+Space` 并选择 **Cassotis 言泉拼音输入法** 即可开始输入。

使用 Fcitx 5 会话时，先把桌面输入法框架切换为 Fcitx 5，再通过 Fcitx 5 配置工具添加 Cassotis。IBus 与 Fcitx 5 可以同时安装，但当前桌面会话应只由其中一个框架管理。

设置界面可以从 GNOME 输入源中 Cassotis 的“首选项”，或 `fcitx5-configtool` 中 Cassotis 的配置操作打开；备用命令是 `/usr/libexec/cassotis-ime/cassotis-settings`。升级时用同样的方式安装新版本；卸载使用 `sudo apt remove cassotis-ime`。

<a id="user-installation"></a>

### SteamOS 等只读系统：用户目录安装

下载与 `uname -m` 对应的便携包（`x86_64` 或 `aarch64`）并核对 SHA-256。在 SteamOS 的**桌面模式**或其他系统目录只读的桌面环境中，将程序安装到个人目录。不要沿用旧包中的安装脚本，也不要运行 `sudo ./install.sh`。请先结束正在输入的拼音，再在当前桌面用户的终端执行以下命令，**不要使用 `sudo` 或 `su`**：

```bash
arch="$(uname -m)"  # 输出 x86_64 或 aarch64
archive="cassotis-ime-linux-2.0.0-${arch}.tar.gz"
sha256sum "${archive}"
tar -xzf "${archive}"
cd "cassotis-ime-linux-2.0.0-${arch}"
./install.sh --user --check &&
./install.sh --user
```

`--check` 只做预检，不安装文件；通过后才执行安装。自动选择时，KDE 优先使用已安装的 Fcitx 5，GNOME 优先使用 IBus；也可以用 `--framework fcitx5` 或 `--framework ibus` 明确选择，两条命令须加上相同的参数。安装器会先检查架构、动态库/ABI 依赖和框架版本，通过后才复制文件。程序安装在 `~/.local/libexec/cassotis-ime`，词库安装在 `${XDG_DATA_HOME:-$HOME/.local/share}/cassotis-ime`，不写入 `/usr`，也不关闭系统只读保护。所选框架需已安装并启用为桌面的输入法框架；安装器不会自动安装依赖或切换框架。

安装后在当前框架中选择 Cassotis；若列表未刷新，重启该框架或重新登录。设置的备用命令为 `~/.local/libexec/cassotis-ime/cassotis-settings`。

便携包附带独立的 OpenCC 简繁转换运行库及数据，在系统缺少它们时使用，不会替换系统动态库。已在 SteamOS 3.8.14 的 KDE X11 桌面、IBus 1.5.32 下验证用户目录安装、升级、卸载和实际输入；未覆盖 SteamOS 游戏模式和 SteamOS 上的 Fcitx 5。如果预检提示动态库不兼容或 Fcitx 版本过低，请使用面向该发行版构建的二进制，不要通过关闭系统只读保护处理。详见[用户目录安装与卸载](BUILD.md#portable-user-installation)。

升级时解压新版便携包，以同一桌面用户再次运行上述预检与安装命令。卸载使用 `./uninstall.sh --user`，**不要加 sudo**；它只移除安装清单中未经修改的程序文件。不要混用系统安装、源码用户目录安装和便携用户目录安装。

### 其他系统：便携包的系统安装

仅当系统目录可写、具有管理员权限且运行库兼容时，才使用以下方式。SteamOS 等只读系统请使用上面的[用户目录安装](#user-installation)。

```bash
arch="$(uname -m)"  # 输出 x86_64 或 aarch64

sha256sum "${archive}"
tar -xzf "${archive}"
```

便携安装器不会自动解决运行库依赖，所需库见 [BUILD.md](BUILD.md)。这种安装使用 `sudo ./uninstall.sh` 卸载。

## 架构
- `src/engine`：拼音解析、候选生成、排序与用户学习，移植自 Windows 版引擎。
- `src/host`：语言模型推理、纠错和后台补全；`src/host/native` 是连接 ONNX Runtime 的 C++20 桥接库和模型的注意力算子。
- `src/service`：两个框架共用的引擎服务（`cassotis-engine`），包括 Unix 套接字服务和空闲内存回收。
- `src/ipc`：适配器与引擎服务之间的通信协议。
- `src/dictionary`、`src/common`：SQLite 访问、用户词库、配置与平台工具。
- `adapters/ibus`、`adapters/fcitx5`、`adapters/common`：两个框架的适配器和 GTK 3 设置程序。
- `data`：词库 schema 和语言模型（`data/models/char_lm`，按编号分块存放）。
- `third_party/onnxruntime`：x86_64 与 aarch64 的 CPU 版 ONNX Runtime 1.20.1。
- `scripts`、`packaging`：构建、安装和打包脚本。
- `tools/control`：服务控制客户端。

## 运行时文件
- `cassotis-engine`：共用的引擎服务，加载词库和语言模型。
- `ibus-engine-cassotis`：IBus 适配器。
- `libcassotis.so`：Fcitx 5 插件。
- `cassotis-settings`、`cassotis-control`：设置程序和服务控制客户端。
- `libcassotis_pinyin_transformer_ort.so`、`libonnxruntime.so.1.20.1` 和 `char_lm/`：推理桥接库、运行库和模型文件。它们只由引擎服务加载，适配器不加载。
- `dict_sc.db`、`dict_tc.db`：基础词库，系统安装位于 `/usr/share/cassotis-ime/`，用户目录安装位于 `~/.local/share/cassotis-ime/`。

缺少引擎服务时，任何框架都无法转换输入。缺少模型文件时，输入法仍可使用，只是候选不经过语言模型排序。

## 构建（快速开始）
前置要求：Linux x86_64 或 aarch64，Free Pascal 3.2.2，C/C++20 编译器，SQLite 3，OpenCC，带 PyGObject 与 GTK 3 的 Python 3，以及 IBus 和 Fcitx 5 开发头文件。不需要 CMake、CUDA、GPU 或系统安装的 ONNX Runtime。

```bash
./scripts/check_environment.sh
./rebuild_all.sh
```

`rebuild_all.sh` 把引擎服务、两个适配器、控制客户端和推理桥接库重新构建到 `build/bin/`，并在核对 SHA-256 后，把 `data/models/char_lm` 中的分块拼成运行时使用的 `char_lm.onnx`。要为当前桌面用户安装源码构建，先从 [Cassotis Lexicon](https://github.com/shenmin/cassotis-lexicon) 取得配套的 `dict_sc.db` 与 `dict_tc.db`，再以当前用户（不用 sudo）运行：

```bash
./scripts/install_ibus.sh --dictionary /path/to/dict_sc.db \
  --dictionary-traditional /path/to/dict_tc.db
# 或
./scripts/install_fcitx5.sh --dictionary /path/to/dict_sc.db \
  --dictionary-traditional /path/to/dict_tc.db
```

不要在 Debian 包之上叠加这种安装。脚本选项和发布打包见 [BUILD.md](BUILD.md)。

## 词库流程
基础词库是 [Cassotis Lexicon](https://github.com/shenmin/cassotis-lexicon) 的 schema-24 SQLite 数据库，由它的生成产物构建：
- 词表：`dict_unihan_sc.txt`、`dict_unihan_tc.txt`、`dict_clean_sc.txt`、`dict_clean_tc.txt`
- 同一目录下由语料训练得到的各张表：词间转移先验、补全先验和短词首选表

v2.3.0 词库含简体 258,694 条、繁体 259,571 条读音记录，包括单字；一个词有多个读音时对应多条记录。词库包含经校对的古典诗词和多音字读音，繁体词表及各张排序信号表统一使用台湾字形。用户词库为 `~/.local/share/cassotis-ime/user_dict.db`；`~/.local/share/cassotis-ime/` 下的词库优先于系统副本。词库格式和指定路径的环境变量见 [docs/DICTIONARY.md](docs/DICTIONARY.md)。

## 模型与排序

### 2.0.0：只留一个语言模型
到 1.0.1 为止，Linux 引擎带着 Windows v1.31.0 的整套独立模型：排序器、评分器、生成器和纠错模型，各自负责某条输入路径的某个阶段。Linux 2.0.0 接过了 Windows v2.0.0 至 v2.2.0 的整合与后续改进：

- **一个模型。** 一个约 1.5 亿参数的字符级自回归语言模型（11 层、1024 维、12,017 个字符的词表、8 位量化），由本项目用独立的中文语料训练，既作为普通语言模型，也以拼音为条件。它为长句的完整候选打分，对照输入的音节修正选中的句子，在短词候选中选择，为一键补全重新排序，并给出和选择长句的 Tab 续写。升级时会删除旧版本的模型文件。
- **七个紧凑模型单元。** 留下三个结构排序器，用于长句搜索和完整候选池；四个小的梯度提升策略把语言模型的分数变成决定：长句选择、短词选择、一键补全和 Tab 续写。它们以与 Windows 版相同的参数编译进引擎。短词无上下文时的选择是词库里预先算好的一张表。
- **分数与调用方式无关。** 模型采用固定的量化范围，注意力由自己的算子计算，同一段文字无论怎样分批、之前算过什么，得到的分数都相同。长句一键一键打出来，与同样的拼音一次给出，候选是一样的。
- **内存更少。** v2.0.0 测试中，模型加载后空闲五秒，引擎服务的常驻内存在 x86_64 上约为 311 MiB，在 aarch64 上约为 320 MiB；1.0.0 约为 437 MiB。这些是历史实测，不代表本轮 v2.1.0 已完成 ARM64 测试。

### 现在的排序方式
- **长句**：受词库约束的搜索给出完整候选，两个排序器决定哪些路径在剪枝中保留，第三个排序器为完整候选池排序。语言模型为排在前面的候选打分，长句策略选出第一和第二候选。简体、全拼输入时，模型还会对照输入的音节和输入位置之前最多 48 个字改写选中的句子，修正少量同音错字；用户词和完整拼音的词库精确匹配不会被改动。
- **短词**：精确候选默认保持词库顺序；只有语言模型的分数（光标前有文字时一并参考）给出明确理由时，短词策略才调整顺序。只有词库可以依据时，由预先算好的那张表决定谁排在前面。
- **词库外的短语**：三到五个音节、既不是词库词也不是用户词的输入，先由词库给出各种切分下的整句草稿；语言模型按“作为一个完整分句是否通顺”为它们打分并选出一个，再对照输入的音节修正。双拼同样适用；开启模糊音、输入中带分隔符 `'` 或使用繁体词库时不启用。
- **英文字母**：输入的字母同时也是中文读法时，语言模型结合上文，在一次调用中比较字母与页面上前几个整词读法；字母明显领先时才排到前面。
- **一键补全**：词库补全和强转移补全立即显示。语言模型在后台为更大范围的词库词重新排序，优势明确时才替换已显示的补全。
- **长句 Tab 续写**：语言模型给出后面的字，并比较补完当前词和续写后面短语的各种方案；Tab 策略选出一个，或者不提示。

### 运行方式
- 全部在本机 CPU 上用随包附带的 ONNX Runtime 计算，不联网，不使用 GPU。
- 只有引擎服务在后台加载模型；普通候选、选词、上屏和静态补全都不等待模型。
- 前台的语言模型调用期限为 100 ms，后台补全为 120 ms；超时的结果被丢弃，保留已有结果。
- 模型的线程数等于可用的 CPU 数，x86_64 最多 6 个，aarch64 最多 8 个。
- 停止输入五秒后，服务归还未使用的堆内存，不卸载模型，也不丢失上下文。

## 基准测试

下表的 `v2.1.0-dev` 是当前开发版的 x86_64 完整原生实测，ARM64 尚待验收；`v2.0.0` 保留上一发行版的历史成绩。自 v2.0.0 起，语料基准不设置搜索、模型或补全的墙钟时限，准确率与延迟取自同一次完整查询，统一使用八个模型线程；确定性搜索的工作量上限和排序规则不变。
测试方法、语料来源和评分规则见 [BENCHMARK.CN.md](BENCHMARK.CN.md)（[English](BENCHMARK.md)）。测试案例与言泉输入法 Windows 版相同，取材于开发者自己的小说 [**《永恒的舞动》**](https://www.qidian.com/book/1037259117/)，并与所有训练数据保持隔离。

2.1.0 开发版于 2026-10-23（UTC+8）在 Ubuntu 26.04.1 x86_64 虚拟机上测得，配备八个 vCPU、16 GiB 内存，宿主为 Intel Core i5-12600K。2.0.0 于 2026-10-17 在同一 x86_64 机器及 Apple silicon 上的八 vCPU、8 GiB aarch64 虚拟机测得，不是受控的硬件对比。本轮测试集包含进一步的读音修正，短词歧义子集由 11,728 条变为 11,685 条，不能把历史版本成绩当作逐条配对对照。延迟单位为 ms。

实际安装的输入法仍保留前台 100 ms、后台 120 ms 保护。不限时成绩不代表限时生产路径总会给出相同结果：此前 x86_64 限时长句测试少了 37 条首选、36 条前两位，这个结果没有被删除，也不能视为已通过修改测试口径修复。完整结果、计时范围及历史实测保留在 [BENCHMARK.CN.md](BENCHMARK.CN.md) 中。

## 配置
设置由共用的引擎服务保存，IBus 与 Fcitx 5 看到的是同一份状态。可从应用列表或框架的 Cassotis 菜单打开 **Cassotis IME Settings**。

重点配置项包括：
- 输入模式（简体中文、繁体中文、英文）与拼音方案
- 各组模糊音
- 标点风格与全角 / 半角
- 连续输入数字后句号是否改为小数点
- 中文模式下识别英文，默认开启
- 中文标点中保持半角的符号，默认 Markdown 预设
- 每页候选数、翻页与补全按键，以及可分别关闭的功能快捷键

用户数据遵循 XDG 规范：用户词库为 `~/.local/share/cassotis-ime/user_dict.db`，服务套接字为 `$XDG_RUNTIME_DIR/cassotis-ime/engine.sock`。全部选项见[配置说明](CONFIGURATION.CN.md)。

言泉输入法 Linux 版 v2.0.0 基于 v2.2.0，用一个字符语言模型和七个紧凑模型单元取代各个独立模型，升级时删除退役的模型文件。三到五个音节的词库外短语由语言模型成句，并对照拼音修正。新增中文模式下的英文识别、U/I/V 快捷输入、数字后的小数点、Markdown 标点预设和可排序的自定义短语；部分纠错与撤销保留原始按键，有歧义的鼻音和元音边界处单字仍可选择。末音节尚在输入时保留补全提示。发布的二进制去除了调试符号，Debian 包改用 XZ 压缩。
